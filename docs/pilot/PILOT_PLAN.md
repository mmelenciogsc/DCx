# Opt-in pilot plan

Status: draft only. The current automated decision is `NO_GO`; no pilot enrollment or telemetry collection is authorized.

The implemented native readiness dashboard consumes the same read-only blocker policy as the JSON report. Its separate local privacy group can enable the existing aggregate-only store or stop and purge it after distinct unchecked approvals. A local administration preview can inspect strictly revalidated recent aggregate buckets and run a seven-scenario in-memory incident stop drill. Those settings and preview actions cannot activate a pilot or production, enroll a participant, collect an event by themselves, transmit data, publish content or initiate a payment.

## Entry conditions

- Signed package install/update/uninstall and rollback pass on clean Windows 11 VMs.
- JAWS, NVDA and Narrator human acceptance has no unresolved major issue.
- OpenAI, PayPal, Facebook/QuickBooks and other provider use is documented, eligible and separately authorized where applicable.
- Privacy notice, terms, CARE/commission policy, consent record and support/incident ownership are approved.
- Every critical/major readiness issue is validated, the automated report changes to `GO`, and the owner explicitly approves activation.

## Proposed stages

1. Internal fixture-only cohort with local models/mocks and no contribution upload or payment.
2. Small opt-in accessibility cohort with production side effects still disabled.
3. Provider sandbox cohort only after each provider acceptance gate passes.
4. Separately approved production pilot with reversible feature flags and payout/live contribution controls still independently gated.

Each participant receives an accessible scope statement, data disclosure, stop/withdraw control and support route. Enrollment is unchecked by default. Leaving the pilot stops future measurement and follows the approved retention/deletion policy.

## Metrics

The implementation defines 12 aggregate metrics: completion rate, duration, input/output token totals, tested CCB reuse ratio, retrieval success, crashes, user-control revocations, false agent claims, accessibility failures, global-sync bytes and CARE reconciliation variance. A default-off local store accepts only these keys and closed enum dimensions, aggregates immediately by UTC day, and purges on opt-out. The native UI exposes the exact local notice, retained-bucket count, separate one-use enable consent and separate stop/purge acknowledgment. It has no product event or network wiring. Metrics contain no prompt, output body, URL, local path, keystroke, field value, provider account identifier or user identifier.

The local administration preview lists only cataloged count/sum/minimum/maximum buckets from the most recent 30 UTC days. Read-time validation denies tampered keys, dates, dimensions or numeric invariants. This is local fixture visibility, not a deployed operator console, cohort roster or remote metric service.

## Stop conditions

Immediately stop the affected stage for credential exposure, unauthorized external action, payout/reconciliation variance, private-data transfer, unrecoverable loss, focus/control safety failure, false high-impact agent claim, inaccessible critical flow, signing/update failure or a severity-one incident. Preserve minimized evidence, disable the relevant feature flag, follow the incident runbook and require a new readiness report before resumption.

The automated local drill verifies the stop/preserve/fresh-readiness plan for seven closed scenarios with zero external actions. Before any pilot, named humans must still conduct approved tabletop and operational exercises with real containment owners and reviewed notification timelines.
