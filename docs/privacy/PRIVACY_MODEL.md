# Privacy model

## Defaults

- Local by default; no user content is contributed or synchronized outward.
- Community contribution opt-in is unchecked and every artifact requires review and approval.
- The global catalog downloads inward as signed content; it cannot read the private store.
- Provider calls disclose the exact payload class and destination before first use and whenever sensitivity changes.
- Usage receipts are minimal and pseudonymous; they contain no prompt, source, artifact body, browser URL history, or file path.

## Data classes

| Class | Default location | Default retention | External transfer |
|---|---|---|---|
| Browser profiles/history | Windows user profile | User-controlled | Website traffic only |
| Task prompts/files | Local private store | Configurable | Task-scoped explicit provider use only |
| API/OAuth credentials | Windows protected secret store | Until revoked | Destination provider only |
| Private CKB/CCB | Local private namespace | User-controlled | Never by default |
| Global replica | Local read-only namespace | Current plus rollback | Download from global service |
| Contribution staging | Local quarantine | Until submitted/deleted | Current client: separately approved literal-loopback simulation only |
| Usage receipts | Local journal + server minimal record | Policy-defined | Qualified event fields only |
| CARE ledger | Authoritative service | Accounting/legal policy | No provider transfer in current evidence; future PayPal/contributor views require approved policy |
| Webhook decision audit | Authoritative CARE service | Accounting/security policy | No transfer implemented in the local fixture |
| PayPal sandbox transport | Transient process memory; provider batch/item references and destination digest in CARE ledger | Byte buffers cleared after operation; durable pseudonymous records follow accounting policy | Disabled/unconfigured until separately approved credentialed sandbox acceptance |
| Recovery archive | User-chosen local path | User-controlled | Never by default |
| Minimized crash reports | Per-user local application data, default off | Maximum 20; purge on opt-out or explicit delete | No transport implemented |
| Update staging | Caller-supplied local staging root (core is not wired) | Until a future updater removes it; policy pending | Inbound manifest/package download only from configured exact HTTPS origin |
| Local dependency transfer set | Per-user local-model storage plus receipt digest/length in Windows Credential Manager | Until a future user-approved removal policy; abandoned strict partials are removed during recovery | Startup is deny-all; public HEAD route observation and payload transfer are separate explicit actions, and current real transfer remains owner-gated |
| Pilot metric aggregates | Local SQLite, default off | Purged on local opt-out; final policy pending | No transport implemented |
| Paused web-video frame question | Random per-operation Windows temp directory and approved loopback model request | Deleted immediately after the request; no intentional answer persistence | No provider upload; visible video rectangle and question go only to loopback Ollama |
| Package installation review | In-memory review session and native window | Released on approval, cancellation, denial or close; no receipt persistence | No transfer; validation mode has no installer or executor |

Retention periods, export/deletion behavior, telemetry consent, regional requirements, and a production privacy notice remain P10/P14 legal-review gates.

The dependency preflight displays reviewed source URLs, lengths and hashes but does not persist browser state, credentials or user content. An explicitly invoked route review discloses public-source HEAD requests and the client's network address to those providers. It reads no response body and retains only counts, expiry, policy digest and exact query-free public transitions in memory for at most two hours; signed query values are absent. Transfer receipts omit source URLs and local source paths; they contain catalog/plan identity plus digest-derived payload names, lengths and hashes. Progress contains only stage, item ordinal/count and byte counts. Stable failure text excludes transport diagnostics. Current-user Credential Manager stores only the protected receipt digest and length binding. The recorded native UIA fixture made zero provider requests; the separately authorized product-reviewer run made only the documented public HEAD requests.

## Current private-store realization

P08 stores each local profile in a different hashed directory beneath the current Windows user's application-data root. Queries open only the selected profile database; no sync or upload code is present. Content-addressed artifacts remain inside that same namespace. Current confidentiality relies on inherited Windows per-user ACLs; the SQLite database is not represented as encrypted at rest.

P10 adds local contribution preparation and keeps it off by default. A prepared item contains only the exact content the user reviewed and begins quarantined. Distinct initially unchecked approvals cover intake, minimized owner status and approved-item withdrawal on one bound literal-loopback simulation origin. CKB intake sends its exact reviewed metadata/body. CCB intake accepts only one explicitly selected, bounded schema-v2 ZIP; it does not enumerate private-store content. The entered full path is cleared after local admission and is not stored, logged or transported. Only the base name, digest and complete admitted textual contents are exposed for review, while manifest identity/version/license and digest are bound to the candidate. Owned package bytes remain in memory only until replacement/clear/close, confirmed intake/status, or reconciliation of an indeterminate result, then are zeroed; displayed review text is removed, but immutable managed-string erasure is not claimed. Status returns only submission ID, candidate digest, lifecycle state, UTC lifecycle times and release sequence—not candidate/body/findings or contributor/reviewer identities. Withdrawal returns the exact binding and release descriptor. The first uncertain or accepted intake disables retry and locks candidate identity until reconciliation or a terminal state. If a confirmed package was cleared and status later reports it missing, complete selection/review/preparation is required again. The one-action token is entered through a password control, cleared after every attempt, and neither saved nor logged; automated evidence scans server diagnostics and retained test data for its value. Owned metadata, envelope, request, artifact and bounded response byte arrays are cleared. The UI has no remote origin, reviewer approval or direct publication action. An authenticated reviewer can inspect exact pending items as required for review. Default-off publication and CCB-review queues persist only job/operation/submission identifiers, candidate digest where needed for binding, server-derived reviewer identity, stable failure code, bounded count and retry/dead-letter/remediation timestamps; they have no candidate, prompt, artifact, exception message or stack field. Process-local request limiting uses an ephemeral SHA-256 of the canonical direct-peer address as its partition key; it neither persists nor reports the raw address and never partitions on a bearer token. Child-process diagnostics retain neither bearer tokens nor candidate bodies, and rejection/qualification records use stable codes rather than matched private values. These test-only paths do not authorize remote or production transfer. Usage receipts intentionally have no prompt, body, browser URL or file-path field. Their local simulation table stores only bounded receipt/nonce, installation and entitlement pseudonyms, resource/version, occurrence UTC, qualified flag and stable decision code. Exact authoritative installation/entitlement binding and transactional replay/day-cap evaluation prevent pseudonym substitution or a cooperating-process race from becoming qualified usage; those identifiers remain linkable pseudonymous data and still need an approved production retention/access/subject-rights policy.

P11's durable sandbox webhook audit stores the event and transmission identifiers, event type, UTC occurrence time, stable reducer decision code, and SHA-256 digests of the canonical payload and subscription identifier. Schema v13 retains the prior bounded provider/accounting fields and adds each earning year/month, period economics, qualified contributor pseudonym and decimal weight, allocation cents, threshold-hold flag, registration digest/time, payout CARE-period ID, and exact ordinal/period/pseudonym/amount binding. These are sensitive linkable financial-attribution records, not anonymous telemetry. Failed-item remediation lineage stores source/target batch and ordinal identifiers, contributor pseudonym, amount, source provider status, replacement snapshot ID, unsalted destination digest, source-result/review digests and approval UTC. Durable state stores no raw webhook body, verification signature/certificate, secret, PayPal credential, access token, provider response, plaintext payout email, payer email/name, prompt, browser history, file path or contributed content. Schema-v12 terminal rows remain without invented period lineage. Production access, retention, contributor notice/export/deletion, dispute, tax and subject-rights policy remain unapproved.

The Windows CARE operations window consumes only aggregate health and opaque blocked-case shapes. Normal mode has no configured source and does not infer zero counts. Its explicit validation fixture contains fixed generated counts/times, has no transport, and retains no operation state outside the process or ignored test evidence. The UI and schema-v2 UIA evidence contain no event, transmission, provider object, plan, subscription, sale, account, recipient or contributor identifier. The server-side durable adapter uses schema-v13 state with no provider request; allocation-level records are not added to the operator/UI contracts. Its default-off loopback API accepts a configured token-verifier digest and separate operator-pseudonym digest, then returns only closed aggregate/case fields or stable errors. Authenticated schema-valid decisions persist UTC, the pseudonym digest, fixed action/decision, reviewed aggregate/case digest, optional aggregate-result digest and chain digests; they contain no raw health/result, bearer token, request body or event/provider/subject identifier. Authentication failures and malformed bodies are not written to finance storage. The optional monitor persists only aggregate status/count/retry/time/capability fields, fixed alert/severity codes, observation/delivery UTC and integrity digests; it does not persist an operator, event, provider or subject identifier. The log sink omits aggregate times, bodies and exceptions. There is no approved retention/pruning policy for delivered alert or disposition records. The unsalted operator pseudonym is linkable sensitive data, not anonymity. Request bytes and computed token digests are cleared, but caller-supplied and transient managed authorization strings cannot be claimed as securely erased. Production identity, centralized audit, notification retention/access/notice and subject-rights handling require separate privacy approval.

The unconfigured PayPal sandbox adapter would transiently handle client credentials, access tokens, webhook evidence, contributor payout email addresses and provider responses. Owned credential/request/response byte arrays are cleared after use; immutable managed Basic/Bearer strings cannot be securely erased. Stable exceptions exclude credentials, provider bodies and transport diagnostics. Durable finance storage contains the bounded provider batch ID, result digest, per-item pseudonym/amount/status, immutable recipient-snapshot ID and unsalted SHA-256 of the exact destination; no token, plaintext email or raw provider body is stored. The digest is linkable and vulnerable to address guessing, so it is sensitive pseudonymous data—not anonymization—and requires access/retention review.

The local owner-approval workflow stores each exact recipient email and binding only in a current-user Windows Credential Manager record under an opaque random snapshot ID. Its bounded JSON index retains only the contributor pseudonym, destination digest, credential target, lifecycle state and UTC audit times; it contains no plaintext email. Exact email is transiently displayed for owner review, edits invalidate approval, successful save clears the inputs, separate default-unchecked approval is required for revocation, canceled/failed saves clean pending credentials, and revocation marks metadata before deleting the protected secret. Finance data, recipient metadata and protected credentials are excluded from the current backup roots. Managed WPF strings cannot be claimed as securely erased. This workflow makes no PayPal request and always reports provider verification and eligibility as false. No credentials were supplied and no PayPal API transfer occurred. Approved retention, subject access/deletion, contributor notice, provider verification, provider-data handling and production credential policy remain accounting, security and privacy gates.

P06 local-model inventory and benchmark evidence contains hardware/model identifiers, capabilities, license digest, timing/token counts, memory allocation and closed pass/blocker fields. It contains no user prompt, user image, real transcript, browser URL, account identifier or production media path; the retained transcript, image and audio inputs are generated fixtures. The quality evaluator accepts expected/actual text, fixture identifiers, vectors and relevance labels only as bounded in-memory inputs; its result contains only aggregate edit/ranking counts and rates, dimensions, resource measurements, unload state and closed failure codes. The strict manifest is read from the user-selected local path and is not copied into application data. Its name, source/license, expected transcripts, corpus/query text and relevance labels are shown or processed transiently for exact local review/scoring. The runner's short-lived approval and schema-v1 evidence retain only domain-separated approval/backend/suite/policy SHA-256 values, DCx capture time and that aggregate result. The per-user store atomically replaces only the latest result for each benchmark type and excludes the manifest path, all fixture/document/query identifiers, raw text, relevance labels and vectors; cancellation does not replace prior evidence. Transcription suite hashing consumes exact WAV bytes/length and expected text under local file leases but excludes paths. Embedding suite hashing consumes exact document/query text and relevance labels. The embedding backend digest includes hashes of the approved model name and reviewed Ollama version; evidence does not contain those plaintext values. Its memory fields contain Ollama-reported loaded-model `size` and `size_vram`, not process listings or operating-system peak working set. Managed in-memory strings and embedding vectors still cannot be claimed as securely erased. Read-only compatibility discovery records only the base name, byte length, public model format and incompatible flag for up to 16 pre-existing `.pt` candidates; it does not retain their directory, content or digest. The per-user Ollama selection file retains only exact installed-model name, model digest, license-text digest and approval UTC for separate vision/embedding choices. Separate Whisper and FFmpeg selection files retain canonical local paths, exact SHA-256 digests, approval UTC and, for FFmpeg, Windows signature evidence. Complete license text is read locally for accessible review but is not copied into selection state. Clearing a binding does not delete user-selected source files. WAV transcription is direct; MP3/MP4 audio is converted to an operation-private leased WAV only after separate FFmpeg approval, then deleted after the approved Whisper call. Transcript text is displayed in memory only; cancel, file replacement and cleared/unavailable binding paths retain no partial or stale transcript, and this boundary writes no transcript database or export. Production frame bytes and prompts are sent only to the exact loopback Ollama origin, leased temporary frames are removed, and inference responses are not persisted by this boundary. Any remote fallback still requires separate approval and remains unavailable for private input without a validated local backend.

The local dependency transfer preflight processes only the public pinned catalog, exact public source URLs, byte counts, SHA-256 values, purpose roles, exact query-free redirect transitions and a destination-volume free-byte observation. Its evidence records only aggregate item/byte/capacity values plus plan and redirect-policy digests. It contains no local path, volume label, file content, account, prompt, media or user identifier and is not persisted by the UI. Initial preflight performs no network action. Free space is volatile, excluded from the plan digest and must be re-observed before any future transfer.

The dependency HTTP boundary sends HEAD only after the user explicitly invokes route observation, then sends GET only after the separate exact-plan-and-policy transfer approval reaches its per-item operation. It sends no account, credential, cookie, referrer, prompt, local path, media or device identifier; proxy use, cookies, automatic redirects and ambient credentials are disabled. Startup, missing and expired sessions are deny-all. The in-memory session binds the exact reviewed plan plus the exact item and exact query-free previous/target HTTPS paths; a different plan is rejected before payload contact or storage creation. Signed query values may be transiently present in request URIs but are neither displayed nor retained in policy evidence, a receipt or public error. Its result and protected receipt add only the canonical redirect-policy digest to the prior public plan/source/byte/content identities. Synthetic tests retain no transferred content outside disposable memory. Both the independent audit and one explicitly authorized clean-tree product-reviewer run made the recorded public HEAD requests. The product run retained no query values or response bodies, persisted no session, and created no transfer approval or coordinator; all real payload GETs remain uninvoked.

The transfer-set coordinator stores payload bytes under digest-derived names and a receipt containing only public catalog/plan identifiers plus item index, byte count and SHA-256. The receipt contains no source URI, redirect target/query, local source path, account, prompt, media, device identifier or approval timestamp. Its exact digest/length protected fact is kept in current-user Windows Credential Manager and excluded from backups. Failed synthetic operations remove their private incoming trees; completed synthetic trees exist only in disposable test roots. The accessible workflow separates route review from default-off single-use transfer approval, supports cancellation, and performs protected reverification and lease-held abandoned-partial recovery. A real transfer still requires explicit owner authorization, contained-license review and an approved retention/deletion policy.

The native local hardware profile is transient and local. It displays OS/runtime architecture, processor name and logical count, physical/available memory, application-data volume totals, and bounded graphics adapter name/provider/Windows driver/registry-reported memory. It omits registry paths, volume labels, serial numbers, PCI/device identifiers and user paths; it is not persisted or transmitted and launches no diagnostic process. P06 automated evidence retains the same coarse hardware/resource fields for reproducibility but no stable device identifier.

The FFmpeg selection file retains only the canonical local executable/license paths, exact byte digests, bounded Windows signature evidence and approval UTC. Complete license text is displayed locally but not copied into state. The real installed candidate's inventory evidence records hashes, size, unsigned status and `approved=false`; it contains no user media path or content. Registration and clear perform no media processing or network transfer and never delete the selected source files.

P07/P12 web-video Q&A is user-invoked against the current shared DCx browser tab. It pauses the largest ready, visible top-document HTML5 video and captures only the viewport-clipped video rectangle, not an intentional full-page screenshot. It sends that image plus the bounded optional question only to the exact approved loopback vision model. Random temporary frame storage is held under an exclusive-write then read-only lease, owned decoded image arrays are zeroed, and the directory is removed after the request. The page URL, cookies and browser profile are not included in the model request. Immutable managed JSON/base64/prompt strings cannot be securely erased. No frame, question or response store or network fallback exists in this boundary. Direct YouTube may fail for embedded/live/protected/provider-controlled playback; no cookie copying, download, access-control bypass or authenticated-provider acceptance is claimed.

P12 package-install review holds the canonical local package path, file URI, file name, size, package/proposal/signer-certificate digests, identity, publisher, version and review times only in the active process and accessible window. The exact file remains under a read-only lease until approval, denial, cancellation or close. The Windows signature child receives the path in its process-only scrubbed environment; the path is absent from command arguments and is not returned in its closed JSON response. Child diagnostics are discarded. No prompt, account, browser session or credential is involved. The validation receipt is not persisted, and the package path or publisher is not written to diagnostics or test manifests by the product boundary. The generated UIA fixture and its synthetic file remain only in the ignored test-evidence directory. No upload, installer process, deployment call or elevation occurs. A future real installer would require a separate retention/logging notice and approval review.

P09's Windows Credential Manager trust-policy anchor contains only schema version, public trust-root SHA-256, highest accepted policy revision and public policy-envelope SHA-256. It contains no account, device identifier, private content, prompt, URL history or credential secret. It is intentionally excluded from DCx backup archives together with global replica files; loss/recovery policy remains a production gate. The persistent replica operation-lock file is empty: it stores no PID, username, path, operation, timestamp or content identity. Replica/service storage admission rejects linked or root paths with stable category messages that omit the local path; concurrency and containment evidence records only pass/fail fixture state.

P13 recovery archives include browser history/bookmarks and private CKB/CCB only. WebView2 profiles, cookies, authenticated sessions, global replicas and Windows Credential Manager secrets are excluded. Archives are not encrypted by the current implementation, so the user-selected destination must be protected appropriately; encryption, retention UI and secure deletion remain release blockers.

P13 minimized crash diagnostics also default off under a versioned notice. An enabled report contains only schema version, UTC time, a closed component category, a closed error category, a terminating flag and application version. The schema has no exception message, stack, dump, prompt, response, URL, path, keystroke, account or user identifier. Atomic bounded files inherit the per-user application-data protection and are capped at 20. The accessible UI can delete reports without changing consent; opt-out purges all reports. No export or network transport exists, and future transfer is not authorized by local consent.

P13 controlled-update admission receives only a signed public release manifest and package from one configured exact HTTPS origin. Its retained signed metadata contains product/package version, public package URI, length/digest, package identity and publisher—not browser history, prompts, private knowledge, credentials or user identity. Redirects, cookies and proxies are disabled, and there is no upload. The core is not wired to the desktop and its synthetic fixtures made no external request; production origin/retention policy still requires review.

P14's pilot metric store persists aggregate counts, sums, minimums and maximums by UTC day, reviewed metric key and closed enum dimension. Its schema has no raw-event timestamp, prompt/output body, URL, local path, keystroke, field value, private artifact body, provider account identifier or user identifier. Recording defaults off; consent notice versions cannot roll back; local opt-out purges aggregates. No product event source or network transport is connected. This implementation is not authorization to collect metrics: an approved notice, accessible enrollment/withdrawal, final retention/deletion policy and explicit pilot approval remain blocked.

Schema v11 blocked-case review keeps raw event/transmission/provider/plan/subscription/sale/account/recipient/contributor identifiers and amounts out of the client contract. It exposes a random opaque 128-bit case reference, closed event kind/reason, attempt count, first/last-attempt UTC times, review digest and latest fixed disposition. The review digest includes the random reference when binding internal identity, reducing simple identifier-dictionary correlation, but the reference, timestamps, operator-pseudonym digest and disposition history remain linkable sensitive pseudonymous data—not anonymity. No free-form note is accepted. `investigation_requested` and `retained_blocked` remain in the finance database as append-only audit evidence; no retention/pruning, operator notice, subject-access/deletion or external-ticket policy is approved. Native UIA evidence uses generated fixed values only. The normal desktop source remains unconfigured and no PayPal or external notification transfer occurred.
