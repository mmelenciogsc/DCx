# Threat model

## Protected assets

User files and prompts; browser sessions; API/OAuth/PayPal credentials; private CKB/CCB; Windows input/focus; local process authority; global signing keys and catalog; contribution provenance; usage receipts; entitlement and CARE ledgers; payout approvals; audit evidence.

## Trust boundaries

| Boundary | Untrusted side | Trusted enforcement |
|---|---|---|
| WebView2 content ↔ client | Web pages, scripts, downloads, DOM text | Origin-aware browser adapter and download quarantine |
| Documents/media ↔ parsers | Files, URLs, embedded objects, OCR text | Type/size limits, sandboxing, safe parsers, output validation |
| Model output ↔ tools | Prompt injection, hallucinated arguments | Typed schemas, policy engine, capability grants, evidence checks |
| UI ↔ Windows broker | Agent action requests | Allowlists, safe argument binding, focus lease, approval/cancel |
| Client ↔ OpenAI | Optional approved task payload | Redaction, minimization, protected key storage, TLS, cancellation |
| Client ↔ global service | Catalog updates/contributions/receipts | Signatures, nonce/idempotency, minimization, quarantine |
| Global service ↔ PayPal | Webhooks, entitlements, payouts | Signature verification, reconciliation, owner approval, sandbox first |

## Priority threats and required controls

1. **Prompt injection causes an OS or financial side effect.** Content-derived instructions have no capabilities. The policy engine requires a typed user-intent grant; destructive, external, privileged, publishing, and financial actions require accessible confirmation.
2. **Focus theft or conflicting input harms the user.** A single control coordinator issues revocable agent focus leases. Any user input pauses agent input. Handback restores a recorded UIA element when safe and otherwise announces a deterministic fallback.
3. **Browser session theft.** WebView2 profiles are DCx-owned, ACL-protected, and never created from Chrome cookies. Secrets are excluded from logs, artifacts, screenshots, crash reports, and model context.
4. **Command injection.** Brokers use executable plus argument-array contracts, canonical paths, workspace scopes, time/output limits, and deny shell interpolation by default.
5. **Malicious dependencies or community code.** Pin packages, record hashes/licenses/SBOM, scan, build in quarantine, test permissions, sign approved artifacts, support revocation.
6. **Tampered global updates.** Verify a pinned trust root, manifest signature, artifact digest, monotonic version, expiry/revocation, and atomic swap; preserve rollback.
7. **Private-data exfiltration.** Upload defaults off. Contributions require item-level preview, ownership attestation, redaction and secret/PII/license scans. Telemetry excludes prompts and source content.
8. **Receipt/payout fraud.** Entitlement-bound signed receipts, replay prevention, anomaly checks, audit sampling, immutable journal semantics, double-entry reconciliation, holds, and final owner approval.
9. **Local denial of service/cost runaway.** Per-task token, time, memory, process, network and retry budgets; model unload; cancel/kill only the scoped child process.
10. **Confused-deputy elevation.** The main app runs unelevated. A future elevation helper must be narrowly scoped, short-lived, separately authenticated, and invoked only after explicit consent.

## Implemented OpenAI/Codex controls through P04

- The child environment is rebuilt from a small OS-variable allowlist; arbitrary parent secrets are not inherited.
- DCx uses an isolated per-user `CODEX_HOME` and ephemeral app-server auth storage, so it does not copy or silently reuse the developer's Codex/ChatGPT session.
- API keys live in Windows Credential Manager, never command arguments or project files. Known values and bearer credentials are redacted from bounded child diagnostics.
- P04 threads are ephemeral and read-only; web search, apps and multi-agent features are disabled. Unhandled server tool requests receive no authority.
- Before `turn/start` dispatch, user cancellation prevents the request. After dispatch, one pending intent is bound to the exact unique ephemeral thread. The first identity-bearing started, delta or completed notification binds the exact turn and permits immediate interruption; the later correlated response must identify that same thread/turn. Conflicting identity, cross-thread turn reuse and ambiguous mappings fail closed. App-server lifetime cancellation and request timeout remain enforced.
- Commercial ChatGPT-plan sign-in remains compiled unavailable until eligibility is evidenced. A model catalog is never considered authorization.

## Implemented BOSS controls through P05

- Task graphs reject duplicate/unknown dependencies and cycles before execution.
- Routing is capability- and privacy-constrained with deterministic-first precedence; unavailable private tasks do not silently route to OpenAI.
- Evidence, attempt, elapsed-time, task-token and aggregate-token gates fail closed. The aggregate breaker prevents later capability execution after overrun.
- Checkpoints record decision metadata and measurements but omit task prompt/output bodies.
- Capability exceptions are classified without persisting exception messages that could contain private content.

## Implemented local-model controls through partial P06

- Ollama owns a loopback-root-only HTTP transport with redirects, cookies and proxies disabled. Every response must remain on the exact approved scheme/host/port. Model names/digests/capabilities, prompts, admitted PNG/JPEG/WebP images, embedding batches, vector dimensions and JSON responses are bounded; malformed inventory, mismatched/incomplete vision results and inconsistent/nonfinite vectors fail closed.
- All Ollama inference acquires one current-user lease before its first request. Shared-client and benchmark paths retain the three-observation quiet fence, exact unload and complete-absence verification. Normal local/shared-viewport vision instead uses one serialized application-owned host, so an unrelated default-service client cannot share its process or port. The lease remains cooperative across DCx processes and does not exclude malicious same-user code.
- Production owned-runtime authority is a separate strict state file authenticated by its own current-user Windows Credential Manager anchor. It binds the exact Authenticode-reviewed executable/CUDA-v13 tree, canonical non-reparse model root and recent approval. Accessible Review starts nothing; separate unchecked Approve/Save re-reviews signer/tree/license identity; Clear revokes authority without deleting content. Rollback, missing anchor, unsafe path, unsigned runtime, stale review or changed official license reference fails closed.
- The app-owned host re-reads protected authority before each use, revalidates and leases every admitted runtime file, clears ambient environment variables, uses a random loopback port/private profile, disables cloud/pruning/Vulkan, forces CUDA-v13 and proves listener ownership by child PID. It permits at most one exact resident model for five minutes. Warm inventory may contain only the requested name or `sha256-<approved digest>:latest`; any other alias/digest, duplicate or unrelated model tears down the whole process. Fresh resource admission runs for a cold load; three exact-resident observations prevent DCx's own VRAM allocation from being counted as another cold load. Failure, cancellation, model switch, approval change/revocation, benchmark isolation and app exit kill the job-owned tree. The direct model root remains shared, loopback Ollama has no client authentication, same-user code can discover the port, and narrow file/process check-use races remain. ADR 0091 records that this is stronger production composition, not malicious same-user isolation.
- Vision and embedding inference require exactly one digest-qualified inventory alias whose 64-hex digest, capability and inspected license-text SHA-256 match the approved selection immediately before and after execution. Mutable names, duplicate names, changed license text and a binding changed during inference fail closed. Loaded resource measurement and unload verification bind by digest because Ollama may canonicalize its process display name.
- Model capability and license metadata are inspected locally. A keyboard/UIA-accessible manager exposes exact identity and complete license text, requires an unchecked-by-default approval, resets approval after save and exposes no acquisition action. Selection respects current free-NVIDIA-memory/available-RAM budgets, excludes non-digest-bound identities and uses deterministic least-resource embedding preference.
- Per-user model selection contains only exact name, model digest, license digest and approval UTC. Separate owned-runtime selection contains the exact runtime tree/signature binding, model-root path and approval UTC, protected by the credential anchor above. Ollama runtime/model, Whisper and FFmpeg selection state plus aggregate benchmark evidence share one local, non-root storage guard: every existing directory ancestor, directory and present target must be non-reparse; paths are revalidated after open and immediately before atomic replacement; unsafe cleanup is abandoned rather than followed. Linked roots/files and settings/evidence directories swapped after open fail without writes through the link. Strict schema/size/name/hash validation still fails closed, and authority can be independently cleared. A same-user check/open race remains for stronger ACL/process isolation to address.
- Remote fallback requires connectivity plus separate provider approval and is unavailable for private input when no local backend exists.
- Whisper registration requires four distinct regular files on a local drive: executable, model and separate runtime/model licenses. Reparse files/ancestors, network/device paths, unsupported types and binary or oversized license text fail closed. The accessible review displays both complete licenses and exact byte digests; approval is default-off, invalidated by path edits and followed by a four-file save-time recheck. There is no download/install action, and clearing preserves the source files.
- Whisper executable, model and license files are SHA-256 pinned. Both license files are reverified before adapter creation. The executable and model are size-bounded and reverified for every run. Verified executable/model files and the signature-checked WAV input remain held by read-only, no-write/no-delete leases through process completion so they cannot be replaced between verification and use.
- Whisper runs without shell interpolation, with a scrubbed environment, typed arguments, timeout/tree kill, transcript size/reparse checks and deleted operation storage. Transcript bytes are held under a read lease, decoded as strict UTF-8, normalized for line endings and rejected on unsupported control characters before reaching the accessible UI. Child diagnostics and canceled partial text are never retained.
- FFmpeg execution requires the separately persisted exact executable/license/signature review. Processor creation revalidates the approved complete-license digest; every run revalidates the executable SHA-256 and holds both executable and signature-checked MP3/MP4 input under no-write/no-delete leases. Absolute paths, typed arguments, a scrubbed child environment, private random operation storage, timeout/tree kill, output-size limits and required WAV/PNG signatures fail closed. The leased output is deleted when the immediate Whisper or Ollama consumer finishes. No media consumer resolves FFmpeg from `PATH`.
- Transcription quality evaluation bounds fixture count/text and total edit-distance cells before work, normalizes deterministically and returns only aggregate WER/CER edit counts/rates. Embedding evaluation bounds corpus/query/dimensions, rejects nonfinite/zero/inconsistent vectors and invalid relevance labels, and returns only aggregate Recall@K/MRR. Both require elapsed and working-set evidence, optionally require GPU evidence, require unload by default, and use closed failure codes without returning transcript text, identifiers or vectors. Caller-supplied fixtures and thresholds remain untrusted until reviewed; evaluator success alone is not model acceptance.
- Benchmark execution requires a DCx-clock-validated explicit approval, at most 30 minutes old, over domain-separated backend/suite/policy digests. Strict bounded manifests reject ambiguous JSON, unknown fields, path escape/reparse/network inputs and duplicate WAV weighting. The keyboard/UIA surface shows exact digests, provenance/license and thresholds; starts approval off; revalidates the manifest, approved backend and suite before one run; and revokes approval after edits or termination. Transcription WAV bytes/length and expected text are rehashed under local no-write/no-delete leases; embedding text/relevance is rehashed and batched by 32. Backend binding is checked around every sequential call, unload is mandatory, substitution fails closed, and cancellation releases leases without replacing prior evidence. Revalidated atomic latest-only evidence omits paths/content/identifiers/vectors.
- The concrete embedding benchmark adapter binds approved model/license identity plus exact reviewed runtime-tree digest and bounded runtime version; rejects malformed version/running-model evidence and any preloaded model; validates vectors/counters; samples one exact post-call target and always attempts exact `keep_alive:0` cleanup under an independent timeout. Benchmark review/run stop any interactive host first, then use a clean owned process. Normal interactive vision intentionally retains only the exact target for bounded follow-up; it rechecks model/license before and after and process exclusivity after each result. Ollama `size` and `size_vram` remain labeled loaded memory, not operating-system peak working set. Same-user port/model-root races remain possible despite the process boundary.
- Current Whisper and embedding successes are deterministic adapter fixtures, not accuracy or installed-backend evidence. P06 remains blocked pending approved binaries/models and real quality/resource benchmarks.
- Digest equality is local runtime byte identity, not publisher authenticity. The accessible approval manager handles only already-installed models; signed provenance, approved acquisition, installation and update/revocation policy remain absent.
- The authenticated dependency catalog deterministically expands the selected set into exact candidate, license and Ollama-layer source/length/digest identities. Exact-source conflicts fail closed, identical source identities are deduplicated without dropping their roles, and a domain-separated plan digest binds the full set and conservative two-copy-plus-512-MiB storage formula. Volatile free-space observations do not change that digest and unknown/insufficient capacity never passes. The UI exposes the exact plan plus a canonical redirect-policy digest and route inventory before a separate single-use unchecked transfer approval, and capacity is rechecked at execution.
- The local-dependency HTTP boundary does not trust a self-consistent plan alone. Production reloads the hash-pinned embedded catalog, re-derives the plan and requires an exact-item approval bound to the reviewed redirect-policy digest plus a passing capacity observation before sending. HTTPS platform trust remains mandatory. Automatic redirects, proxy use, credentials, preauthentication, cookies and decompression are disabled, and response-header size is bounded. Startup is canonical deny-all. An explicit user-invoked reviewer can issue only bounded HEAD requests and create a non-persisted two-hour schema-v2 session whose transitions bind item source/length/digest and exact query-free previous/target HTTPS URIs, never a host or directory prefix. The live policy separately carries the reviewed plan digest; the item transport and set coordinator reject a different valid plan before provider payload contact or storage creation, including direct-only/subset substitution. Signed queries are transient and absent from authority/evidence. Missing, expired, changed or substituted sessions deny before a new payload request; a change during transfer removes partial output. Unsafe/relative targets, IP literals, loops and more than three hops are rejected; every hop uses a fresh credential/cookie/referrer-free identity/no-store request and verifies its response URI. Final status, declared length, range/encoding headers, streamed byte count and SHA-256 fail closed. A rejected destination is untouched. After an empty writable/seekable destination is admitted, every ordinary denial, cancellation, timeout, callback, transport/stream failure or content mismatch attempts unconditional truncate/rewind/flush. Unexpected cleanup failure produces only `dependency_transfer_cleanup_failed`; that destination is untrusted and the set coordinator removes its complete incoming operation directory. Stable public codes omit transport details. The separate command-line HEAD-only auditor remains evidence-only and cannot create a product session.
- The transfer-set coordinator binds both plan and redirect-policy digests in explicit set/item approvals, rechecks current policy and capacity before storage, confines random incoming content under non-reparse per-user roots, and accepts only exact item-result identities including policy digest. Its deterministic source-path-free schema-v2 receipt records the historical policy digest; current-user Credential Manager protects the complete receipt before atomic publication. Verification requires that protected fact and exact directory inventory, then rehashes every payload under a no-write/no-delete read share. A later policy change does not invalidate protected historical provenance or authorize reuse. Existing completed sets are immutable. One in-process gate serializes transfer, verification and cleanup. Operation failure/cancellation, including a progress-observer failure before commit, deletes only its own strict random incoming directory. After atomic publication or full verification, non-authoritative progress-observer failure cannot contradict the durable success result or trigger deletion. Recovery recognizes the strict name shape, refuses links and runs only while the product holds its exclusive data-root lease. Same-user code/races remain outside this boundary.
- The accessible workflow never contacts a provider automatically. **Observe current provider routes** is a distinct explicit action with its own cancellation and a notice that only public HEAD requests occur. Its result exposes counts, expiry, digest and every query-free transition but leaves transfer approval unchecked. One later unchecked exact-plan-and-policy approval enables one transfer and resets after every outcome. Retaining the displayed snapshots prevents changed policy from becoming silently approved at keypress. During payload work only cancellation remains available; item/byte progress omits URLs, paths and diagnostics. Completion is announced only after protected full-set reverification, and separate keyboard actions reverify or recover. Environment/root-gated native fixtures prove default-off approval, unique access keys, focus, policy review and cancellation with synthetic data and zero provider requests; they are not real acquisition evidence. Owner authorization, human AT, contained licenses and backend acceptance remain blocked.
- Native product hardware profiling uses `GlobalMemoryStatusEx`, runtime architecture, `DriveInfo`, bounded read-only machine registry keys, System32 DXGI and the installed NVIDIA driver's exact `%WINDIR%\System32\nvml.dll`. It executes no diagnostic process or network request and returns no registry path, PCI address, DXGI LUID or stable device identifier. DXGI enumerates at most 16 non-software adapters, bounds names, rejects ambiguous duplicate-name matching and derives remaining local process budget from the documented budget/current-usage fields. Native/COM failure yields no DXGI observation. Every current-memory observation separately states whether it is eligible for local-model GPU admission. Only the independently benchmarked NVIDIA NVML path is currently eligible; DXGI-only Intel/AMD or otherwise unvalidated observations are inventory-only. Vision uses at most 70% of eligible current NVIDIA free memory and embedding at most 25% of current Windows available memory, recaptured under the inference lease immediately before work. Missing eligible live GPU telemetry denies GPU admission. These volatile observations are not reservations and do not prove GPU execution, peak use or workload quality; external-client isolation and real benchmark evidence remain mandatory.

## Implemented content controls through P07

- Local admission canonicalizes paths, rejects direct reparse files, applies per-kind size ceilings and verifies binary signatures before viewer/parser dispatch.
- Office ZIP/XML extraction caps entry count and expanded data, prohibits DTDs and external XML resolution, and never executes embedded code or objects.
- OCR-derived geometry and repaired semantics must validate before export; display-only content is not silently converted into an editable field.
- YouTube admission requires HTTPS, an exact supported host and a valid video identifier; credentials, lookalikes and unsupported page types are denied.
- Media does not autoplay. Local MP4 frame extraction and MP3/MP4 audio extraction require the exact user-approved FFmpeg binding and the leased processor controls above. Local and web frame questions use only the exact user-approved, digest/license-bound loopback Ollama vision model and leave playback paused for follow-up questions or user-controlled resume.
- The local-model manager can review and persist an exact existing FFmpeg executable/license binding with real Windows Authenticode status and default-off approval. The measured installed candidate is unsigned and remains unapproved outside disposable validation profiles. Native fixture UIA proves approved MP3 extraction composed with approved Whisper, clear-binding denial, and real local-frame extraction through an isolated approval; it does not establish production publisher, licensing, quality or performance acceptance.
- A web-frame request is an explicit user action against the current shared DCx tab. It selects only the largest ready, visible top-document HTML5 video, clips its finite bounded rectangle to the viewport, pauses it and captures only that rectangle. The page URL, browser profile and cookies are not model inputs, and there is no remote-model fallback.
- Page content, including text inside the captured frame, is untrusted evidence and cannot grant tool authority or override the visual-evidence-only prompt. Question length, geometry, playback time, image/base64 and response sizes are bounded. Random temporary image storage transitions from an exclusive writer to a read-only/no-write/no-delete lease; owned decoded image buffers are zeroed and operation storage is removed.
- Resume is a separate action bound to the same tab and page. Navigation, missing/hidden/unready video, invalid geometry, protected capture, unavailable or changed model identity, and provider-controlled playback fail with stable content-free states. The implementation does not traverse cross-origin frames, download provider media, copy cookies, or bypass DRM, advertising, login, MFA, age, region or rights controls.
- HTML/DOCX exports are newly generated semantic artifacts rather than modified untrusted source packages. Human review remains necessary before relying on OCR or model descriptions.

## Implemented private-knowledge controls through P08

- Private profile identifiers map to distinct hashed directories; databases, vectors and artifacts are never queried across those roots.
- Optimistic version checks and SQLite transactions prevent silent lost updates. Resource bodies and vectors are bounded and validated before insertion.
- Content-addressed writes verify declared SHA-256 and use same-directory atomic moves. CCB reads repeat artifact integrity, package identity and provenance checks.
- CCB ZIPs reject traversal, absolute/backslash paths, duplicates, symbolic links, excessive entry/expanded size, malformed manifests and missing entrypoints.
- CCB publisher trust is pinned by subject-public-key info. Canonical ECDSA signatures bind code digest and meaningful metadata; an untrusted publisher, changed body or changed package fails closed.
- Artifact packages are data, not executable authority. Only a host-registered adapter with matching identity/digest and passing bounded fixtures becomes a BOSS capability; package code is not dynamically loaded.
- FTS input is tokenized into a bounded parameterized expression. All relational writes and queries use parameters rather than concatenated user content.

## Implemented global-replica controls through partial P09

- Every canonical release is ECDSA-signed and binds its sequence, previous signed-release SHA-256 and resulting canonical-catalog SHA-256.
- Clients stage bounded chunks, preserve interrupted partials, verify descriptor digest/signature/chain/result, write immutable generation files and atomically replace only the active pointer.
- Wrong signatures and conflicting sequences fail before activation. Prior signed generations support explicit rollback after verification under the current trust policy; the protected floor deliberately does not pin the release sequence.
- A pinned offline P-256 root signs canonical trust-policy snapshots. Policies bind monotonically chained revisions and release-key SHA-256 identities, sequence windows and revocation points; a fresh client downloads every retained policy revision before accepting releases.
- Trust-policy history is durable in the authoritative SQLite registry and transferred in bounded digest-checked chunks. Stale/conflicting policy state, a non-root policy signature and a revoked release signer fail closed.
- The Windows client stores the highest accepted trust-policy revision, exact policy digest and trust-root digest in a strict per-user Credential Manager record outside replica files. A lower/missing/conflicting local policy fails closed. File-first/anchor-second updates recover only one signed predecessor-linked crash-window revision.
- A rollback target is verified under the current anchored trust policy before pointer replacement, so restoring older replica files cannot erase a recorded emergency revocation or corrupt the current active pointer. The anchor is not hardware-backed: same-user deletion of both credential and replica state, root custody/ceremony, anchor recovery, TLS identity and external review remain unresolved.
- Global replicas are keyed by trust-root hash under a separate `global` directory and never receive a private-store handle. Two-client tests preserve a private sentinel.
- Replica and authoritative registry roots, ancestor chains and operation-time release/catalog/staging/artifact/database/WAL/shared-memory files must remain local, non-root and non-reparse. The service accepts only the exact digest-derived artifact relative path and one exact P-256 signing key; linked roots/files, swapped directories and metadata redirection fail before use. This narrows path escape but does not eliminate same-user check/open races; production ACL/mount/service-account isolation remains required.
- Every open/status/policy/sync/rollback/search/artifact operation for one replica root is serialized by a canonical-root process gate plus a persistent regular no-share lock file. Contention is cancellable and bounded; lock-file links fail closed, and normal release keeps the empty file in place to avoid a close/delete/recreate split-lock race. This prevents cooperating client/process checkpoint, policy, anchor-reconciliation and pointer races. It is not protection from arbitrary code already running as the same user, which can still tamper between separate checks, delete protected state or deny service.
- Artifact metadata is signed with the catalog. Bodies remain lazy, content-addressed and size/digest verified; authoritative publication rejects missing artifact records.
- The native global-knowledge surface receives only a global-replica view source and no private-store handle. It never synchronizes on open, refresh or search; synchronization requires a distinct user action. Unconfigured state does not claim an empty or current authoritative catalog. Search input is bounded to 512 characters, rejects non-whitespace controls before storage work and returns at most 20 displayed records. Stable UI failures omit paths, transport diagnostics and untrusted bodies.
- Normal startup admits one exact registry authority only through a separate review. The candidate must be one bounded local regular non-reparse exact P-256 SubjectPublicKeyInfo file and one canonical HTTPS base address; literal-loopback HTTP is validation-only. The review binds base file name, size, SHA-256, canonical address and UTC time, and makes zero network requests. Approval is initially disabled/unchecked, expires after 30 minutes and is destroyed by any candidate change.
- The strict versioned enrollment record contains the public key, digest, exact origin and approval time solely in current-user Windows Credential Manager. Unknown fields, malformed Base64, digest conflicts, noncanonical origins and unsupported versions fail closed. Replacement repeats exact review/approval; clear has a separate initially unchecked acknowledgment. Credential Manager does not defeat arbitrary same-user code or provide hardware monotonicity.
- Source composition creates no replica storage or HTTP handler while unenrolled. With valid enrollment, open/status/search remain offline; only explicit synchronization can contact the exact origin through a 30-second no-redirect/no-cookie/no-proxy/no-decompression client. An enrollment change disables the old source until close/reopen, and close disposes the HTTP lifetime. A malformed protected record exposes only replacement/clear and infers no remote state.
- Before signature processing, every registry descriptor must return from the exact requested URI as unencoded `application/json` with optional UTF-8 charset. Declared and streaming bodies are independently capped at 16 KiB; comments, trailing commas, duplicate/unknown fields, excess depth, invalid sequence/revision/digest and impossible signed-object sizes fail closed. Temporary descriptor/read buffers are cleared after parsing.
- Policy/release/artifact chunks require unencoded, charset-free `application/octet-stream`; both declared and streamed bytes are capped at the exact requested count. Invalid revisions, sequences, ranges, counts and artifact digests are rejected before network contact. Production composition enables certificate-revocation checks, caps response headers at 16 KiB and permits two registry connections. Signature/chain/digest/atomic-activation checks remain mandatory after this admission layer.
- Sealed native fixtures require an explicit startup argument and contained disposable data-root gate. The signed-replica fixture uses ephemeral P-256 material, synthetic resources and an in-memory transport with zero sockets. The enrollment fixture uses an isolated in-process store and cannot touch the real user credential. They are validation evidence, not production root provenance or deployment.
- The HTTP client requires HTTPS except for literal loopback HTTP. The simulation server refuses startup without its explicit simulation flag, data root and external key file.
- Container context excludes secrets and runtime data; the Compose definition is read-only/non-root/no-new-privileges. It remains unexecuted because Docker access is blocked.

## Implemented contribution controls through partial P10

- Contribution preparation defaults off, and each changed item invalidates its prior review/approval digest and prepared object. Local preparation always yields quarantine. Intake, minimized status and withdrawal each have a separate initially unchecked approval and are restricted to the exact prepared object and one bound literal-loopback simulation origin.
- CCB selection admits one bounded regular non-reparse ZIP as an exact in-memory snapshot. The full path is cleared and never enters the candidate, transport or status; only the base name, SHA-256 and complete admitted text are shown for review. Manifest identity/version/license and artifact digest are bound into the candidate, and scanning covers the contribution body plus all admitted package text/test inputs.
- Rights/license/sensitive-data attestations, bounded approval age and unique nonces are revalidated at authoritative intake; client-provided scan results are not trusted.
- Scanner findings store only stable codes, not matched secrets or PII. Risky/dummy content cannot transition to approved.
- Approved CKB metadata enters the signed release path; withdrawal emits deprecation. The local server fixture permits a CCB transition only after exact package admission and passing authoritative sandbox evidence.
- Contribution HTTP routes are absent by default. Explicit simulation enablement requires distinct SHA-256 credential digests and bounded pseudonymous identities for contributor and reviewer roles. Bearer tokens are compared in constant time, transient token buffers are zeroed, contributor status/withdrawal is owner-scoped, and stable errors and process diagnostics exclude credential and contribution bodies.
- Enabled contribution routes are covered before endpoint work by a process-local fixed-window request and concurrency policy. Canonical direct-peer addresses become ephemeral SHA-256 partition keys; raw addresses and credentials are not retained or reflected. Partition count, configuration, timestamps and request leases are bounded/fail closed, but restart and multi-node coordination remain intentionally unsupported.
- The versioned contribution envelope rejects unknown or duplicate metadata fields at every depth, comments/trailing commas, undeclared/changed length, unsupported versions and content over the shared metadata/artifact/Kestrel bounds. Intake requires the exact parameter-free binary media type and no content encoding. Contributor identity is server-derived and must equal the reviewed candidate; reviewer identity is never accepted from the request. Owned metadata and request-read buffers are cleared after use.
- The Windows simulation client has fixed intake, exact-owner-status and withdrawal paths and rejects non-root, non-HTTP, host-name and non-loopback origins. Redirects, cookies, proxies and decompression are disabled; response headers/connections, time/body, exact requested URI, unencoded JSON media/charset and duplicate-free schema are bounded before exact submission/candidate/state checks. Status omits candidate/body/findings and contributor/reviewer identities. A first attempt binds the origin; duplicate send remains disabled until that origin reports missing; cancellation/invalid results require reconciliation. Candidate identity is locked for an uncertain or accepted nonterminal lifecycle. CCB bytes remain only for reconciliation after an indeterminate result and are zeroed after confirmed intake/status, replacement, clearing or close; a missing server item after local clearing requires complete reselection/review/preparation. The bounded printable bearer token is cleared after each attempt and excluded from logs/persistence; owned metadata/envelope/request/artifact/response byte buffers are zeroed. Managed-string erasure is not claimed.
- A server-side rootless Bubblewrap prototype now executes hostile BusyBox-shell fixtures in separate user/mount/PID/network/IPC/UTS/cgroup namespaces. It drops all capabilities, clears environment, runs as 65534, exposes only digest-bound read-only package/input/runtime mounts, remounts root read-only and applies bounded CPU/address-space/process/file/descriptor/output/wall limits.
- Sandbox evidence binds the claimed artifact, canonical extracted workspace, test suite, policy launcher, Bubblewrap, runtime and output digests. Outside-quarantine paths, links/special files, digest substitution, host/system reads, external network, root writes, inherited secrets, timeouts and output floods fail closed in the local hostile gate.
- Exact schema-v2 package intake uses digest-addressed quarantine, identity/version/license and two-component CycloneDX/runtime closure, safe extraction, rescanning of every textual component and test input, all-test execution, durable minimized evidence, expected-output verification and signed artifact propagation. Tampering or a missing executor fails closed.
- Approval and withdrawal persist immutable reviewer-authorized intents before registry mutation. The registry atomically binds the digest-derived operation ID to a canonical change-set digest and release; startup validates a bounded batch and atomically advances local state/intent completion without duplicate releases. Recovery rehashes candidate and artifact data, while changed intent/candidate/artifact bytes fail closed.
- Pending intents have separate database-backed execution leases with random instance owners and fencing tokens, five-minute expiry/renewal and a 20-attempt ceiling. Claiming never changes the reviewed change set or grants authority. Completion requires the current unexpired token in the same transaction as state advancement.
- Concurrent local service instances claim a pending intent once. An expired worker cannot complete after takeover, malformed lease state fails before overwrite and the signed registry's stable operation ID remains the final duplicate-release defense.
- A second exact simulation gate enables a bounded hosted worker. It persists exponential retry and dead-letter state containing only operation/submission identifiers, stable failure code, bounded count and timestamps. Five transient failures or one permanent policy failure stops automatic work. Reviewer remediation reschedules the existing immutable intent and cannot change its authority or content.

## P11 opaque blocked-case review

- The authenticated API returns only closed event-kind/reason/disposition codes, attempt count, UTC times and the random reference/digest. Unknown fields, identifier-bearing response substitution, stale review digests, missing approval and nonzero provider/financial effects fail closed.

## P07/P12 reviewed document export boundary

OCR text, labels, language and geometry are untrusted even when generated locally. Export validation bounds block count, per-field and aggregate character counts, identifiers, reading order and geometry; invalid XML characters and unrecognized language tags fail before output creation. HTML text/attributes are encoded. DOCX is emitted through `XmlWriter`, defines only internal relationships and creates no hyperlink, macro, embedded object or external relationship.

HTML and DOCX are serialized to a random temporary in the destination directory and replace an existing output only after complete serialization, flush and cancellation checks. Failures clean the temporary best-effort and leave the old destination unchanged. The UI disables concurrent export actions and reports stable failures without filesystem/exception details. Extension confusion is denied. This protects product-mediated replacement, not a destination-directory attacker, reparse-parent substitution, filesystem rollback, secure deletion or malicious same-user access to the chosen export directory. Output and a briefly present temporary contain document content. Microsoft Word interoperability and human assistive-technology acceptance remain blocked.

The URL-to-PDF branch admits public HTTPS only and rejects credentials, fragments, redirects, cookies, proxies, ambient credentials, decompression and literal nonpublic addresses. Its custom connection callback resolves and connects only to one admitted public address, and the response must have exact `application/pdf`, bounded headers/time/length, `%PDF-` and `%%EOF`. An exact literal-loopback HTTP origin is available only under an explicit test flag. The downloaded bytes remain in a random private operation directory until wizard close. Residual DNS/resolver, malicious public endpoint, Windows PDF/OCR parser, filesystem-reparse race and same-user-process risks remain.

Flattened PDF generation requires reviewed geometry and binds the exact OCR-reviewed source SHA-256 to the later no-write render lease. Each source page becomes a bounded operation-private PNG; page count, per-page/aggregate bytes and aspect are bounded, and failures roll back partial images best-effort. The semantic model becomes encoded CSP-locked local HTML with that raster letterboxed at preserved aspect and text coordinates transformed into the same placement. A random private WebView2 profile may navigate only to that exact HTML; scripts, web messages, password/autofill features, context menus and developer UI are disabled. The bounded DevTools response must be one base64 field and decode below 96 MiB. Atomic replacement additionally requires PDF markers, `/StructTreeRoot` and `/MarkInfo`; a test-only parser verifies raster sample dimensions/placement/aspect, extracted golden text and normalized coordinates. For validation only, the parser also bounds image count/dimensions/decoded bytes, hashes and writes deterministic PNGs to a fresh non-root directory, and abandons cleanup rather than following a reparse point, subdirectory or unexpected filename. ImageMagick independently normalizes each generated source page and enforces positive RMSE/changed-pixel thresholds plus RGB-inversion thresholds on monochrome-landscape, color-gradient-portrait and mixed-color-landscape content. The native gate also mutates the reviewed disposable source, requires stable denial and unchanged prior destination, restores the exact fixture bytes, and only then admits a successful export. Decoded byte arrays are cleared, but immutable managed strings cannot be securely erased. The experimental DevTools contract, Windows PDF rendering, parser/runtime vulnerabilities, destination-directory attacks and secure deletion remain residual risks. The pixel gate covers a deterministic generated three-page corpus, not representative real-world, photographic/skewed/damaged/unusual-color-profile scans, AcroForm fields, PDF/UA or human acceptance.

## P04 notification/response cancellation ordering

Codex protocol messages may expose an exact thread/turn in a notification before the correlated `turn/start` response, or place a terminal notification immediately after that response before an awaiting continuation runs. User cancellation intent is therefore registered before dispatch and binds to the first exact identity-bearing turn notification. Response-reader binding remains a fallback, and the eventual correlated response must agree. Exact identity checks, bounded request timeout and app-server lifetime cancellation remain in force. DCx never interrupts an inferred "latest" turn and rejects a cross-thread or conflicting identity. This closes all three observed local fixture races but does not establish real-provider behavior.

## Security gate policy
