# DCx product / technical specification v1.0

## Product thesis
DCx ('Agentic Browser') is a native Windows 11, accessibility-first, intent-driven browser, file browser, document/media viewer and general-purpose **locally executed** agentic computer environment. User and agent share the same fully interactive web/file viewport, with reversible input/focus handoff and accessible progress. Native applications that cannot render inside DCx can launch and foreground outside it, remaining user-operable. Agent capabilities include browser/DOM, UI Automation, screenshots/VLM, command line, native tools, document manipulation, sanctioned external APIs and installer-managed approved dependencies. User can interrupt, direct, approve, or take over any step. Accessibility targets JAWS, NVDA and Narrator, with equivalent status/control via keyboard, UI Automation, and accessible text.

## Hard architectural boundaries
1. **Local Windows client:** WebView2 browser with distinct persistent profiles; file/media viewers and download manager; browser-agent synchronization; accessibility semantics; OS UI automation and process/terminal broker; installed **local** Codex process/app-server; BOSS orchestrator; model-adapter/router; Ollama for compatible local models; independent local Whisper runtime; private CKB/CCB; read-only cached global CKB/CCB; usage event journal; secure local secret store.
2. **Shared global Ubuntu server:** authoritative curated global CKB/CCB catalog, vectors/metadata/artifacts, signed incremental releases; API for opt-in sanitized contribution submissions and validation; subscription entitlements; anonymous/pseudonymous usage receipts and CARE accounting; PayPal sandbox/production webhooks and payout batches. **No routine user Codex execution, files, prompts, credentials, or personal content on owner server.**
3. **Customer device deployment:** WSL may be used for the developer's current build and tests but must not be implicitly required on ordinary customers' Windows installations. Use native Windows subprocess/PowerShell or explicitly optional environment features. No unofficial scraping of Chrome cookies or transplanting sessions into WebView2; authenticated websites use user-controlled WebView2 profiles, permitted API OAuth, or separately consented supported existing-browser control.
4. **AI providers initially only OpenAI:** user-provided OpenAI developer API keys and eligible, officially supported ChatGPT-plan / Codex app-server sign-in. These are distinct entitlements and billing paths. Commercial ChatGPT-plan usage is conditional on OpenAI approval/eligibility; implement blocked/unavailable UI state and fully functional API-key path. Do not claim subscription confers unrestricted API access.
5. **Revenue:** US$3/month recurring PayPal Business subscriptions; optional contributor checkbox initially unchecked; contributors propose sanitized licensed CKB/CCB artifacts subject to explicit approval. Aggregate pool **at most 40% of positive defined distributable net profit** (not 40% to each contributor). Usage-weighted allocation, Net 60 = 60 calendar days after monthly earning-period close, reconciliation/holds/refunds, PayPal Payouts eligibility, audit trail, minimum threshold and idempotency. Do not send live payouts without owner approval. Profit definition must be documented and counsel/accounting-reviewed.

## Core design
- **Native shell:** Windows 11 app (choose WinUI 3 versus WPF after verifiable feasibility comparison), WebView2 for the interactive web surface, keyboard-first tab/address/bookmarks/history/downloads and accessible tree, content navigation and screen-reader status.
- **Dual execution surfaces:** a) WebView2 viewport for user+agent with stable focus, nav events, DOM/ARIA inspection, accessible labels, configurable repair overlay, independent manual operation; b) foregrounded external Windows apps (UIA, process broker, keyboard/mouse fallback) with focus handoff and user takeover. Capture agent actions and confirmations with provenance.
- **Document and media:** PDF.js or suitable PDF rendering; safe local file handlers, DOCX/XLSX/PPTX parsing/rendering via maintained compatible libraries; editable exports with structural validation; screen-reader-inaccessible scanned PDF conversational wizard, OCR/geometry mapping and output verification; local/video web frame pause-describe-resume where source supports pause/seek, no false promises for unbuffered live calls; text/audio/image Q&A using local/cloud vision.
- **BOSS orchestrator:** structured task graph, state machine and checkpointing; discover available CCB tools before generation; roles PLANNER, RESEARCHER, CODER, DEBUGGER, REVIEWER, VALIDATOR, EXECUTOR and SECURITY_REVIEWER (roles are configurations, not necessarily separate costly LLM calls); select deterministic tools first, then vetted CCB, local inference, economical OpenAI model, expensive model only on justified escalation; log route reasons, estimated and actual API token cost, latency, verification outcomes, failure recovery. Model lists and prices discovered from currently supported provider APIs/docs, not hardcoded assumptions. Budget caps and circuit breakers.
- **Inference:** hardware inventory (RAM, physical/usable GPU VRAM, GPU drivers/backends, disk, CPU). Ollama for compatible quantized local VLM, language, embedding models; independent Whisper.cpp or compatible local transcription backend; model download hashes/licenses, quantization selection through measured benchmarks, sequential load/unload and CPU fallback; never force local if unsuitable.
- **CKB/CCB:** separate private user collections and read-only global replica collections, with vector retrieval, structured metadata DB, content-addressed artifact store and signed manifests. CKB = version-aware official docs, tutorials, samples, vetted explanations, citations/provenance, date and expiry. CCB = licensed reusable functions, scripts, modules, integrations, pipelines, tests, dependency locks, permissions, OS/version compatibility, SBOM and publisher signature. Retrieval is permission-filtered; private content is not synchronized or published by default. Full locally searchable global catalog and incremental atomic signed updates; large artifacts lazy-download upon actual need. Offline search and rollback.
- **Community contribution:** opt-in unchecked checkbox plus per-artifact review before any upload; user owns/has rights, redact secrets/PII/proprietary material, scan for malicious content/dependencies, human/automated policy review, sandbox tests, staged publication, attribution graph for derived modules, deprecations and revocations. Quarantine anything unsafe. Signed minimal usage receipts that do not contain private prompts or source content; reject replay, self-use inflation, fabricated usages, invalid entitlements, and failed events. User-owned devices cannot be cryptographically assumed honest: fraud controls and audit sampling required.
- **CARE:** authoritative double-entry/immutable ledger semantics: subscription receipts, costs, adjustments, approved net income, contributor pool allocations, withheld/eligible/pending/paid states, PayPal webhooks and payout responses, refunds/chargebacks and reconciliation. Idempotent events and UTC accounting periods; transparent contributor dashboard. Sandbox first; do not assume live PayPal capabilities or regulatory treatment.
- **Security:** least privilege process broker; narrow action grants and OS-elevation confirmation; no blanket automatic installs; verified trusted download sources and hashes; no secret logging; Windows DPAPI or approved Credential Manager vault; safe subprocess argument binding, domain restrictions and prompt-injection trust boundaries; downloaded websites/docs are untrusted data; strict IPC schemas; local file access isolation and WebView2 profile separation; sensitive approval accessible to screen reader; explicit user confirmation for sends, payments, deletion, permission changes, installs/elevation and publishing.

## Representative acceptance scenarios
A. Search own historical Facebook post from authenticated **DCx profile**, show live navigable browser, let user log in manually, return inspected direct URL and accessible results; demonstrate fallback when Facebook blocks automated access and no fabricated post result.
B. Retrieve permitted QuickBooks sandbox data through authorized API, generate real XLSX with formulas/tables/date/currency data and validate against fixtures; no live financial data required for CI.
C. Enter scanned-image PDF URL, download safely, use accessible conversational form wizard, produce fillable/flattened saved PDF with visual/coordinate and text extraction checks.
D. Pause controllable local/YouTube video, inspect a frame via suitable VLM, resume; handle nonseekable live limitations explicitly.
E. Repair unlabeled demo web controls/inferred tabular layout via opt-in semantic overlay without breaking site functionality or cursor; test JAWS/NVDA/Narrator manually.
F. Launch Windows Calculator/Notepad or controlled demo native app; agent interacts through UIA, user takes over, agent resumes without focus theft.
G. Build and run approved portable command/tool with prompt-injection, privilege and malware safeguards; validate logs/rollback.
H. Sync signed global release to local replica while offline/reconnected; corrupt/tampered release rejected; private user collection unchanged.
I. Opt-in contribution submission and server validation, qualified usage receipt, revenue accounting ≤40% of positive distributable net and Net 60 using PayPal SANDBOX/mocks; no real payout.
